# 명해원 기능 확장 PRD

## 1. 문서 개요

- 서비스명: `명해원`
- 슬로건: `하늘의 뜻을 읽어 내일을 준비하다`
- 문서 목적: 기존 사주 분석 플랫폼을 결제·구독·리포트·질문형 경험이 결합된 수익화 서비스로 확장하기 위한 제품 기준을 정리한다.
- 적용 범위: 웹 서비스 1차 출시부터 향후 `명해원 PRO SaaS` 확장까지 포함한다.

## 2. 서비스 정의

명해원은 사주 분석, 운세 해석, 궁합, 월운, 길일, 저장함 기능을 제공하는 웹 기반 사주 분석 플랫폼이다.

이번 확장의 목적은 기존 사주 분석 기능을 유지하면서 아래 기능을 추가해 재방문과 유료 전환이 가능한 구조를 만드는 것이다.

- 정밀 사주 PDF 리포트
- AI 질문하기
- 단건 결제
- 월 구독
- Premium 권한 관리
- Supabase 기반 사용자 데이터 보호
- 향후 철학관용 PRO SaaS 확장

## 3. 제품 목표

### 3.1 현재 구조

사용자 분석 실행 → 결과 확인 → 종료

### 3.2 목표 구조

사용자 분석 실행 → 결과 저장 → 정밀 리포트 구매 → AI 질문 → 월운 구독 → 재방문 → Premium 전환

### 3.3 핵심 성과 목표

- 무료 방문자를 회원가입 사용자로 전환한다.
- 분석 결과를 유료 리포트 구매로 연결한다.
- 월운과 오늘의 흐름으로 반복 방문을 만든다.
- 구독형 Premium을 통해 월 반복 매출을 만든다.
- 이후 상담사용 PRO SaaS로 확장 가능한 데이터 구조를 미리 설계한다.

## 4. 개발 원칙

### 4.1 반드시 지킬 것

- 기존 사주 분석 로직은 수정하지 않는다.
- 기존 결과 화면의 기본 동작을 깨지 않는다.
- 신규 기능은 기존 기능 위에 모듈 방식으로 추가한다.
- 결제 관련 시크릿 키는 클라이언트에 노출하지 않는다.
- 결제 승인 검증은 서버에서만 처리한다.
- Supabase Auth 기준으로 사용자별 데이터 접근을 분리한다.
- 모든 개인 데이터는 본인만 조회 가능해야 한다.
- 무료/유료 기능 경계를 명확히 구분한다.
- 환불, 결제 실패, 중복 결제 상황을 고려한다.
- 관리자 페이지에서 결제 내역과 사용자 권한을 확인할 수 있어야 한다.

### 4.2 비목표

- 기존 무료 사주 분석 엔진의 전면 재작성
- 1차 출시에서 정기결제 전체 구현
- 1차 출시에서 철학관용 다중 지점 SaaS 전체 구현

## 6. 핵심 기능 요구사항

### 6.1 정밀 사주 PDF 리포트

목적:

사용자가 기본 분석을 본 뒤, 더 깊은 해석을 PDF로 구매할 수 있도록 한다.

사용자 흐름:

1. 사용자가 사주 분석 결과를 확인한다.
2. 결과 화면에 `정밀 PDF 리포트 받기` 버튼을 노출한다.
3. 사용자가 버튼을 클릭한다.
4. 결제 화면으로 이동한다.
5. 결제 성공 후 PDF 리포트가 생성된다.
6. 사용자는 마이페이지 또는 저장함에서 PDF를 다시 다운로드할 수 있다.

PDF 구성:

- 기본 사주 정보
- 핵심 요약
- 성격 분석
- 강점
- 약점
- 직업운
- 재물운
- 연애운
- 대운 흐름
- 올해 흐름
- 조심해야 할 시기
- 추천 행동
- 종합 조언

정책:

- 결제 성공 전에는 전체 PDF를 다운로드할 수 없다.
- 미리보기는 일부만 제공한다.
- 결제 후 동일 리포트는 재다운로드 가능해야 한다.
- PDF 생성 실패 시 결제 성공 상태와 분리하여 재생성 가능해야 한다.

### 6.2 AI 질문하기

목적:

사용자가 분석 결과를 본 뒤 추가 질문을 할 수 있게 하여 체류시간과 유료 전환을 높인다.

사용자 흐름:

1. 분석 결과 하단에 질문 입력창을 제공한다.
2. 사용자는 자신의 사주 결과를 바탕으로 질문을 입력한다.
3. 시스템은 사용자의 사주 데이터와 질문을 함께 참고하여 답변한다.
4. 무료 사용자는 3회까지만 질문할 수 있다.
5. Premium 사용자는 월 20회 질문할 수 있다.
6. Pro 이상은 더 높은 제한 또는 무제한으로 제공한다.

예시 질문:

- 올해 이직운은 어떤가요?
- 지금 사업을 시작해도 괜찮나요?
- 결혼운은 언제 강한가요?
- 재물운이 좋아지는 시기는 언제인가요?
- 지금 만나는 사람과 궁합은 어떤가요?

정책:

- 단정적 미래 예언 표현을 금지한다.
- 의료, 법률, 투자 판단을 확정적으로 안내하지 않는다.
- 답변 하단에 참고용 안내 문구를 포함한다.
- 질문 기록은 사용자별로 저장한다.

### 6.3 월운 구독

목적:

사용자가 매월 명해원에 재방문하도록 만들고 반복 매출을 만든다.

사용자 흐름:

1. 사용자가 Premium에 가입한다.
2. 매월 사용자 사주 기준 월운 리포트가 생성된다.
3. 대시보드에 이번 달 운세 카드가 노출된다.
4. 사용자는 월운 상세 리포트를 확인한다.
5. 이메일 또는 알림으로 월운 업데이트를 안내한다.

월운 구성:

- 이번 달 핵심 키워드
- 금전운
- 연애운
- 직업운
- 건강운
- 인간관계
- 좋은 날짜
- 주의할 날짜
- 추천 행동
- 피해야 할 행동

정책:

- 무료 사용자는 월운 요약만 확인 가능하다.
- Premium 이상은 상세 월운을 확인 가능하다.
- 월운은 매월 자동 생성되어야 한다.

### 6.4 오늘의 흐름 카드

목적:

매일 재방문을 유도한다.

표시 정보:

- 오늘의 한 줄 조언
- 금전운 점수
- 연애운 점수
- 건강운 점수
- 인간관계 점수
- 행운 색상
- 행운 시간
- 주의할 행동

위치:

- 로그인 후 대시보드 상단
- 모바일 첫 화면
- 오늘의 일진 메뉴

### 6.5 운세 캘린더

목적:

사용자가 특정 날짜의 흐름을 직관적으로 확인하게 한다.

기능:

- 월간 달력 표시
- 좋은 날 표시
- 주의할 날 표시
- 결정하기 좋은 날 표시
- 계약, 이동, 만남, 공부, 사업 등 카테고리별 필터

정책:

- 무료 사용자는 일부 날짜만 확인 가능하다.
- Premium 사용자는 전체 월간 캘린더 확인 가능하다.

## 7. 인증·데이터·보안 요구사항

### 7.1 인증

- Supabase Auth를 사용한다.
- 로그인 사용자는 본인 데이터만 조회 가능해야 한다.
- 관리자 권한은 별도 `role` 로 관리한다.
- PRO 사용자는 본인 고객 데이터만 접근 가능해야 한다.

### 7.2 주요 데이터 그룹

- 사용자 프로필
- 저장된 사주 정보
- 분석 리포트
- PDF 파일 정보
- AI 질문 기록
- 주문 정보
- 결제 내역
- 구매 권한
- 구독 정보
- 궁합 리포트
- 월운 리포트
- PRO 고객 정보
- 상담 기록

### 7.3 RLS 정책 요구

- 모든 사용자 개인 데이터 테이블은 RLS를 활성화한다.
- 사용자는 본인 `user_id` 와 연결된 데이터만 조회 가능해야 한다.
- 사용자는 본인 데이터만 수정/삭제 가능해야 한다.
- 결제 내역은 사용자가 조회만 가능해야 한다.
- 결제 생성, 승인, 권한 부여는 서버에서만 처리해야 한다.
- 관리자 계정은 운영 목적의 제한된 조회 권한을 가진다.
- 서비스 역할 키는 클라이언트에 노출하지 않는다.

## 8. 결제 PRD

### 8.1 결제사

초기 결제사는 `토스페이먼츠` 를 우선 검토한다.

이유:

- 국내 사용자 친숙도
- 결제위젯 제공
- 단건 결제 연동이 빠름
- 이후 정기결제 확장 가능

대안:

- 포트원
- KG이니시스
- 나이스페이먼츠

### 8.2 1차 결제 범위

1차에서는 단건 결제만 구현한다.

대상 상품:

- 정밀 사주 PDF 리포트
- 궁합 심층 분석
- 연간 운세 리포트

정기결제는 2차로 분리한다.

### 8.3 단건 결제 흐름

1. 사용자가 상품 구매 버튼 클릭
2. 서버에서 주문 생성
3. 결제창 호출
4. 사용자가 결제 완료
5. 결제 성공 페이지로 이동
6. 서버에서 결제 승인 검증
7. 결제 금액과 주문 금액 비교
8. 결제 내역 저장
9. 구매 권한 생성
10. 상품 접근 허용

### 8.4 구독 결제 흐름

2차 구현 범위이다.

1. 사용자가 Premium 가입
2. 카드 등록 또는 최초 결제
3. 결제사에서 정기결제용 키 발급
4. 서버에 구독 정보 저장
5. 매월 자동 결제
6. 결제 성공 시 구독 유지
7. 결제 실패 시 유예 기간 부여
8. 반복 실패 시 구독 정지

### 8.5 결제 실패 처리

처리해야 할 상황:

- 사용자가 결제창을 닫음
- 결제 실패
- 결제 승인 전 네트워크 오류
- 결제 성공 후 리포트 생성 실패
- 중복 결제 요청
- 환불 요청
- 구독 결제 실패

### 8.6 관리자 결제 관리

관리자는 아래 정보를 확인할 수 있어야 한다.

- 사용자
- 상품명
- 주문번호
- 결제금액
- 결제상태
- 결제일
- 환불상태
- 권한 부여 여부

## 12. 검수 기준

### 12.1 기능 검수

- 무료 사용자는 유료 리포트 전체를 볼 수 없어야 한다.
- 결제 성공 후 권한이 즉시 부여되어야 한다.
- 결제 실패 시 권한이 부여되면 안 된다.
- 같은 주문이 중복 결제되지 않아야 한다.
- PDF 생성 실패 시 재생성 가능해야 한다.
- 본인 리포트만 조회 가능해야 한다.
- 다른 사용자의 생년월일 정보에 접근할 수 없어야 한다.
- Premium 만료 시 유료 기능 접근이 차단되어야 한다.

### 12.2 보안 검수

- 결제 시크릿 키가 브라우저에 노출되지 않아야 한다.
- Supabase service role key가 클라이언트에 포함되지 않아야 한다.
- RLS가 활성화되어야 한다.
- 관리자 페이지는 관리자만 접근 가능해야 한다.
- 개인정보는 본인 또는 권한 있는 관리자만 접근 가능해야 한다.

### 12.3 사업 검수

- 사용자가 결제해야 하는 이유가 명확해야 한다.
- 무료 기능과 유료 기능 차이가 화면에서 보여야 한다.
- PDF 리포트 구매 버튼이 분석 결과 화면에 노출되어야 한다.
- Premium 가입 혜택이 대시보드에서 보여야 한다.
- 환불정책과 문의 경로가 명확해야 한다.
